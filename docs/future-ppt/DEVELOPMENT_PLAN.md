# AI 动态演示开发计划

更新日期：2026-10-16。状态：后续研发执行计划，功能尚未完成的部分均列为待办。

本计划承接产品需求和 v0.2 路线讨论，作为接下来任务排序与验收的入口。与早期方案有差异时，以本计划的优先级和开发边界为准；历史资料保留供查阅。

## 产品定位与交付目标

面向产品与技术讲解者，将资料生成可直接修改、随讲解推进、可持续更新的 Web 演示。用户像修改 PPT 一样改字、换图、调整位置和节奏，不必为了常见微调重新生成整页。

HyperFrames 已有 Agent 创作流程、Studio 编辑器、SDK、Player 和 Slideshow。我们的重点是让这些能力组成可靠的使用流程，并对支持的内容明确保证：生成后可修改，AI 更新保留无关人工修改，现场演示状态可预测。

第一份完整交付是一份两到三个讲解阶段的产品或技术演示：AI 生成后，用户改标题、替换 Logo、整体移动模块、调整动画终点，再让 AI 修改另一个对象；保存重开后，仍能逐步讲解、进入细节并返回。

首版不承诺任意 HTML/JS 无损可编辑、完整 PPTX 兼容、专业后期特效全集或多人实时协作。视频导出保留上游能力，但不作为动态演示 MVP 的前置门槛。

## 开发边界

- 直接在 HyperFrames 原生 Studio（本地 5190）、SDK 和 Player 上开发。已删除的独立 Future PPT 原型不恢复，不新增另一套独立编辑器。
- 优先复用选择、文字编辑、素材替换、变量、结构化操作、持久化和历史机制；先查现有实现，再决定补充什么。
- 初期沿用 HTML Composition 与上游编辑机制。明确项目中 Overrides、源码和历史各自职责，不增加与 HTML 竞争的 JSON 真源。
- 不要求每个元素单独生成文件。要求支持的关键元素身份稳定、属性可定位、动画引用可追踪。
- 统一总时间轴是待验证的技术选择。作品内动画时间、演示阶段状态、演讲者实际停留时间必须区分。
- 每一阶段只实现通过本阶段验收所需的最小改动。维护上游改动清单，记录无法直接复用的原因。

| 项目 | 当前状态 | 后续处理 |
| --- | --- | --- |

| SDK 部分测试、Slideshow 部分测试 | 已通过 | 不等同于完整浏览器演示验收 |

## 首版编辑契约

以下是待实现和验证的产品约束，不代表上游对任意作品已有此保证。

| 内容 | 用户可改什么 | 应保持什么 | 超出范围如何处理 |
| --- | --- | --- | --- |
| 普通标题、正文 | 文案、字号、颜色 | 容器身份、入退场时序和缓动 | 文案变长允许重新排版，但检查溢出；逐字动画另行处理 |
| 图片与 Logo | 素材、适配、裁剪 | 容器身份及动画绑定 | 比例变化采用明确适配规则，不自动改变场景布局 |
| 基础图形 | 未被动画控制的填充、边框、圆角 | 无关样式及动画 | 修改动画控制属性时明确提示作用范围 |
| 运动对象 | 整体位置、动画终点、时长 | 未被请求改变的轨迹与时序 | 无法安全改写时明确说明，不静默改变操作含义 |
| 数字组件 | 起始值、结束值、格式、时长 | 计数逻辑及容器动画 | 优先使用上游变量；不直接修改被脚本覆写的显示文字 |

普通布局编辑默认目标是整体调整；进入动画编辑后才修改特定动作或关键帧。具体如何映射到现有 Studio，需要审计和浏览器实验后确定，不能仅关闭自动关键帧便宣称完成。

复杂 SVG 形变、Canvas 内部对象、任意逐字动画首版不作统一可编辑承诺。界面应说明可修改的范围，保留现有高级编辑入口。

## 阶段一 验证原生编辑并确定最小改动

目标：证明用户可以方便地完成常见微调，并准确找出缺口。

- [ ] 梳理文字、图片、样式、位置和动画修改到保存、预览、撤销的链路；确认历史由哪一层管理。
- [ ] 在仓库现有夹具或示例体系中增加可追踪的标准作品，在原生 Studio 中打开，不创建独立应用。
- [ ] 标准作品包含普通标题、图片、基础图形、显式位置动画和参数化计数；覆盖静态属性与动画驱动属性。
- [ ] 先记录原生流程的操作步骤、耗时、失败现象，再做必要的交互修正。
- [ ] 验证改标题、换图、改颜色、整体左移 5px、修改终点和修改计数目标。
- [ ] 对有缺口的操作补充最小实现，保存、重开、撤销、重做后复验。

验收：支持范围内操作无需改源码或重新请求 AI；文字及素材修改保留既定动画参数；整体位移在多个采样时刻均为预期偏移；终点修改不影响其他对象。操作入口应明确区分整体布局与动画节点。

交付：标准作品、编辑能力表、必要的 Studio/SDK 改动、针对关键行为的回归证据。至少覆盖起始、中间、结束和反向 seek；不同长度文字及不同比例图片需检查实际画面。

## 阶段二 验证 AI 与人工修改共存

目标：AI 生成的作品遵守编辑契约，后续 AI 修改可以限定范围并回退。

- [ ] 定义最小生成规则：支持的元素、稳定身份、动画目标、参数和可编辑范围。
- [ ] 用现有 Agent 工作流生成标准作品，不以新建聊天界面作为前提。
- [ ] 将局部修改映射到现有 SDK 操作或受控源码修改，记录实际变更对象和属性。
- [ ] 用户先改标题、位置，再要求 AI 修改另一个对象；对比修改前后的目标与非目标内容。
- [ ] 定义同一属性冲突规则：明确指定该属性的请求可以修改；宽泛请求默认保留人工决定，无法兼容时展示冲突。
- [ ] 校验通过再应用到作品；失败恢复最近稳定版本。AI 与人工编辑沿用明确的历史管理方式。

验收：目标对象正确更新，非目标人工修改保留，对象身份未无故重建；AI 更新可整体撤销，保存重开后结果一致。至少覆盖无冲突修改、直接冲突和生成失败三种情况。

交付：生成与局部编辑约定、最小 AI 调用流程、变更记录和回归用例。完整 AI 产品外壳可后续补充。

## 阶段三 打通现场演示与最小交付

目标：作品能被真实讲解和持续使用，而不只是预览动画。

- [ ] 复用 Slideshow，实现并实测下一步、上一步、阶段停留、热点展开及返回主线。
- [ ] 在真实浏览器验证演讲者和观众视图同步，而非仅依赖组件测试。
- [ ] 先完成编辑态修改、保存、恢复演示；演示中快捷编辑在核心闭环稳定后再做。
- [ ] 验证资源、字体、窗口尺寸和重开后的状态。
- [ ] 评估并复用现有发布或交付能力，提供另一浏览器可打开的只读演示入口或可运行项目包；首版不依赖完整 SaaS。
- [ ] 面向观众的交付不暴露作者编辑权限，发布前完成资源和运行检查。

验收：两到三个阶段可以完整讲解，任意停留不造成动画失控；进入细节后能返回预期状态；第二个浏览器能打开交付物。用户更新作品后无需重做整份演示。

交付：完整演示样例、演示状态规则、可复现运行或分享说明、真实浏览器验收记录。

## 阶段四 验证跨阶段对象并决定底层扩展

目标：以真实讲解需求验证跨页连续性，不为预设架构重写引擎。

- [ ] 选择一个架构节点，跨两个讲解阶段展开细节并返回，明确需要持续的是逻辑身份、运行实例还是视觉连续性。
- [ ] 比较上游 Composition、子场景和 Slideshow 的实现方式。
- [ ] 验证前进、回退、长时间停留、分支返回、seek 和保存重开。
- [ ] 若使用固定时间区间，额外验证区间变长或变短时的绑定策略。
- [ ] 记录数据来源、属性所有权、层级与点击区域规则，形成架构决策记录。

验收：对象连续性符合预先声明的语义，不要求手工修改两份重复内容；状态变化可复现，既有编辑和 AI 修改流程仍成立。

只有现有模型无法稳定满足已验证的产品需求时，才立项扩展 Instance/Binding 或编译层。若跨阶段效果不能改善讲解体验，可延后，不阻断基础 MVP。需求若在前三阶段暴露，可提前做局部实验，但不据此扩大重构范围。

## 任务顺序

| 顺序 | 任务 | 依赖 | 完成证据 |
| --- | --- | --- | --- |
| 1 | 编辑链路审计与标准作品 | 当前环境 | 能力表、原生操作记录 |
| 2 | 普通文字、素材及样式微调 | 1 | 动画保持、重开及撤销证据 |
| 3 | 整体位置、终点与时长语义 | 1 | 多时刻轨迹比较、无意外关键帧 |
| 4 | 数字组件参数化 | 1 | 改目标值后播放与 seek 一致 |
| 5 | AI 输出契约与局部修改 | 2、3、4 | 人工修改保留、冲突及失败回退 |
| 6 | 演示控制和只读交付 | 5；原生演示审计可提前 | 真实演讲者及观众流程 |
| 7 | 跨阶段对象专项与架构决策 | 3、5、6 | 场景实验、决策记录 |

任务状态初始均为待办。按验收结果推进，不把工期估算或“AI 完成 99%”当作事实承诺。

## 验证与进度记录

- 不重写已有通用测试。新增测试围绕本次修改的实际失败模式，优先使用现有测试设施。
- 修改被其他包引用的代码后，先构建相应包，再运行依赖方测试。仓库操作使用 Bun。
- 新增或修改 Composition 后执行 lint 和浏览器 check；未通过的问题明确记录并修复，不通过关闭检查隐藏。
- SDK 或源码序列化测试证明数据变化；真实浏览器证明排版、运动、选择及演示状态。两者分开记录。
- 每项交付记录输入、操作、预期、实际结果和证据位置；修改 Studio/Player 时保留前后效果。
- 比较相同微调任务在原生流程和改进流程中的步骤、耗时、误操作及恢复成本；样本数和测量条件一并记录，不将单次结果当成普遍结论。
- 本机 8 GB 内存，默认小作品、单测试 worker。暂不扩展到 4K、多任务渲染或全量媒体回归。

下一次执行从任务 1 开始：在原生 Studio 中建立标准作品，验证现有编辑行为，再提交必要的最小改动。当前计划本身不意味着任何待办能力已经完成。
